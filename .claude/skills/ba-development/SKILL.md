# BA Development Cycle

Работай в `/home/elkinva/projects/ba`. Не меняй защищённые файлы:
`CLAUDE.md`, `technical_specification/**`, `docs/spec/**`, `.env*`,
`certs/**`, `creds/**`, глобальные настройки Claude/DeepSeek.

## Порядок

1. Найди точный пункт ТЗ и acceptance criteria. Если требований нет или они
   противоречат друг другу — остановись и задай вопрос владельцу.
2. Проверь текущее состояние и зависимые компоненты. Сними baseline тестов
   и lint; зафиксируй, если проверки недоступны.
3. Составь минимальный план: файлы, миграции, security/backward-compat
   риски. Не расширяй scope без необходимости.
4. Выбери модель: flash для рутины и небольших правок; v4-pro для
   архитектуры, сложной логики и крупных изменений — предпочтительно в
   отдельной сессии/субагенте (см. `.claude/README.md`).
5. Реализуй доменную логику в `services/`, thin views/serializers; type
   hints, ruff (line-length 100, double quotes), mypy.
6. Добавь/обнови тесты: happy path, edge cases, отказ, гонки,
   идемпотентность. Запусти целевые тесты, lint, types; для миграций —
   `makemigrations --check --dry-run`, `migrate --plan`.
7. Проведи независимый review через `ba-code-review` или `code-reviewer`.
   Исправь найденное; не оставляй известные дефекты.
8. Зафиксируй фактические команды/результаты, изменённые файлы, риски и
   один следующий шаг. Не коммить, не push и не деплой без задания.

## Критерий завершения

- Acceptance criteria выполнены и подтверждены тестами/проверками.
- Нет незакоммиченных изменений защищённых файлов.
- Review выполнен; критичные замечания закрыты.
- Отчёт содержит статус Done/Partial/Blocked и фактическую evidence.
