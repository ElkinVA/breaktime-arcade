# BA Debugging

## Порядок

1. Зафиксируй симптом: команда, URL, окружение, exit code, stack trace,
   версия и последние изменения. Не пересказывай ошибку без evidence.
2. Воспроизведи минимально: один тест, один запрос или один management
   command. Не используй разрушительные команды и не меняй данные.
3. Локализуй слой: URL/view → serializer/service → model/DB → cache/broker
   → infra. Проверь логи, healthz/readyz и `git diff`.
4. Сформулируй 1–3 гипотезы и проверь их по одной. Не «исправляй» вслепую
   несколько мест одновременно.
5. Внеси минимальный fix; добавь regression test, который падал до fix.
6. Запусти целевые тесты, затем lint/types и связанные проверки. Если
   проверка недоступна — укажи это.
7. Проведи review diff; зафиксируй root cause, fix, evidence и остаточный
   риск.

## Критерий завершения

- Есть воспроизведение до и успешный regression test после.
- Fix не маскирует ошибку и не ослабляет permissions/CSRF/CSP.
- Нет изменений защищённых файлов и пользовательских данных.
- Фактические результаты отражены в отчёте.
