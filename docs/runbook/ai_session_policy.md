# AI session hygiene — practical policy

**Дата:** 2026-11-23. Цель — не допускать неоправданно долгих интерактивных
сессий и повторного чтения одного и того же контекста. Это операционная
практика, а не жёсткий лимит и не изменение модели/маршрутизации.

## Interactive / CLI sessions

1. Одна сессия — один значимый task boundary. После завершения задачи
   зафиксируй handoff в `docs/handoff/NOW.md` и начни следующую задачу в
   новой сессии (`/clear` или новый запуск), а не продолжай накопленный
   контекст в 300k+ токенов.
2. Перед закрытием сессии запиши: что сделано, commit hash, проверки,
   остаточные риски, следующий шаг. Это дешевле, чем восстанавливать
   контекст из длинной истории.
3. Не перечитывай полностью `NOW.md`, `PROJECT_STATUS.md`, `BACKLOG.md`,
   `OWNER_DECISIONS.md` на каждом шаге. Используй
   `docs/handoff/ARCHITECT_BRIEF.md` и точечные Grep/Read по нужному
   разделу/ID.
4. Не держи открытыми несколько параллельных интерактивных сессий по
   одному проекту: это дублирует чтение и риск конфликтов.

## Dev Control (`claude --bg`)

1. Держи не более одной активной фоновой сессии на проект.
2. После завершения задачи останови сессию (`claude stop` / кнопка stop),
   не оставляй её idle на часы.
3. `/continue` используй для продолжения конкретной задачи, а не как
   постоянный фоновый режим; автозапуск следующей сессии не включается без
   отдельного решения владельца.

## Autonomy (`claude -p`)

1. Каждая роль — отдельный invocation без `--resume`; между ролями
   передаются только срезы (developer/QA report, diff), а не полная история.
2. Architect стартует с `docs/handoff/ARCHITECT_BRIEF.md`, а не с полного
   набора реестров; детали читаются точечно под конкретную задачу.
3. Developer/QA/Reviewer не повторяют полный suite и уже зафиксированные
   проверки; используются targeted tests и diff-scoped review.
4. Расход фиксируется в `.autonomy/invocations.jsonl` (OBS-001/002). Для
   оценки эффекта сравнивай `by_session`/`by_task` и `input_tokens` до/после,
   не выдавая оценку за измерение.

## Что не делать

- Не вводить `TOKEN_BUDGET`/`COST_BUDGET` и автоматические остановки по
  токенам/стоимости.
- Не менять модели/маршрутизацию и число агентов ради экономии.
- Не сокращать обязательные проверки, независимый review или анализ
  безопасности.
