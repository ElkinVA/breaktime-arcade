# OWNER_DECISIONS — Breaktime Arcade

Файл разделяет три самостоятельные категории:

- **A. Решения владельца** — только явно утверждённые владельцем решения.
- **B. Нормативные требования и технические замечания** — требования ТЗ и технические выводы, которые не являются решениями владельца.
- **C. Ограничения отдельных задач** — временные ограничения конкретных заданий, а не архитектурные инварианты проекта.

До BA-DOC-001 решения владельца существовали только в истории диалогов; здесь они впервые сохранены в проекте. Отдельного подписанного acceptance-файла нет.

Дата фиксации: 2026-11-19 (актуализация BA-DOC-002).

аудитами эти решения не подтверждались и не заменяются. Дата исходных
сообщений, если она не указана в записи, не сохранялась; дата фиксации не

### A.2. Accept-Language и выбор языка

| ID | Решение | Уточнение |
|---|---|---|
| OD-ACC-001 | `q=0` всегда исключает соответствующий язык из выбора | Исключение не допускается даже для резервного `en` |
| OD-ACC-002 | Региональный вариант с `q=0` исключает базовый активный язык | `en-US;q=0` исключает активный `en`; `en-US;q=0.9` выбирает `en` |
| OD-ACC-003 | При наличии `*` выбирается первый активный язык, не исключённый через `q=0`, в порядке `sort_order` | Порядок активных языков берётся из БД |
| OD-ACC-004 | `*;q=0` означает отсутствие приемлемого языка | Результат — HTTP 406 |
| OD-ACC-005 | При равных значениях `q` сохраняется порядок языков в заголовке | Стабильный порядок заголовка |
| OD-ACC-006 | Полностью некорректный заголовок игнорируется | Используется fallback `en` |
| OD-ACC-007 | При частично некорректном заголовке некорректные элементы пропускаются, корректные обрабатываются | Не отбрасывать весь заголовок из-за одного плохого элемента |
| OD-ACC-008 | Если все активные языки исключены или нет приемлемого языка — HTTP 406 | Не подменять отсутствие приемлемого языка другим языком |
| OD-ACC-009 | Явное исключение `en;q=0` обязательно соблюдается | Fallback `en` не используется, если `en` исключён и нет другого приемлемого языка |
| OD-ACC-010 | `de;q=0` при активном и не исключённом `en` даёт fallback `en` | Соответствует утверждённому примеру владельца |

Технические примеры, утверждённые владельцем:

```text
en;q=0, *;q=0.5    -> первый активный язык по sort_order, кроме en
de;q=0.9, fr;q=0.9 -> de
*;q=0              -> 406
de;q=0, при активном en -> en
полностью некорректный заголовок -> en
частично некорректный -> обработать корректные элементы
```

### A.3. Отсутствие обязательного `en`

| ID | Решение | Уточнение |
|---|---|---|
| OD-EN-001 | В активных языках обязателен `en` | Отключение `en` — ошибка конфигурации |
| OD-EN-002 | Не выбирать автоматически первый попавшийся язык вместо `en` | При отсутствии `en` публичная маршрутизация должна сообщать об ошибке конфигурации |
| OD-EN-003 | Проверка `en` должна использовать актуальное состояние БД, не общий TTL-кэш | `QuerySet.update()`/`bulk_update()` не должны обходить проверку |
| OD-EN-004 | При отсутствии активного `en` публичные маршруты возвращают HTTP 503 | `/healthz` остаётся доступным; readiness отражает `i18n: fail` |

Поведение при инфраструктурных ошибках, ранее записанное как `OD-EN-005`, не подтверждено как отдельное решение владельца; оно перенесено в B.2 (`TECH-EN-005`).

### A.4. HTTP-семантика языковых маршрутов

| ID | Решение | Уточнение |
|---|---|---|
| OD-HTTP-001 | `406 Not Acceptable` используется при отсутствии приемлемого языка при корректном списке активных языков | Не заменять 406 на fallback, если язык исключён |
| OD-HTTP-002 | `503 Service Unavailable` используется при отсутствии обязательного `en` | Ответы 503 должны содержать `Vary: Accept-Language` |
| OD-HTTP-003 | Strict 404 для неизвестного языкового префикса | `/xx/games/` не перенаправляется на `/en/`, возвращается 404 |
| OD-HTTP-005 | Для валидных языковых URL переключатель сохраняет path и query-string | Обычный путь и query не теряются |

`OD-HTTP-003` остаётся решением владельца: Strict 404 для неизвестного языкового префикса. Поведение переключателя при неизвестном префиксе **не выводится автоматически** из Strict 404 и рассматривается отдельно в B.2 (`TECH-HTTP-004A`). Использование внешних URL и защита от open redirect также рассматриваются отдельно (`TECH-HTTP-004B`, `TECH-HTTP-004C`). Прямого подтверждения этих положений как отдельных решений владельца нет. Границы `OD-HTTP-002`: 503 при инфраструктурных ошибках получения активных языков не подтверждён отдельно и вынесен в B.2 (`TECH-EN-005`); в A остаётся 503 при отсутствии обязательного `en`.
