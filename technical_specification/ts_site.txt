BA-PLAT-4.2

**Редакция:** 4.2 от 12.11.2026. Заменяет BA-PLAT-4.1 целиком.
**Совместимые документы:** `BA-GAME-2.2`, `BA-SDK-1.1`, `BA-ENV-1.1`.
**Ключевое изменение:** добавлен полный контур «создал ZIP → загрузил в CRM → проверил → опубликовал» без программирования и деплоя.

## §2.0. Область действия, термины, нормативные слова

**Продукт:** международный портал коротких браузерных мини-игр с независимыми таблицами рекордов, оценками, мультиязычным интерфейсом и CRM для управления без программирования.

| Термин | Определение |
|---|---|
| Игровая сессия | Серверная запись одной партии: субъект, игра, версия, режим, состояние, срок жизни |
| Билет запуска | Одноразовый короткоживущий секрет **родительской страницы**; в iframe не попадает |
| Субъект | `User` либо `AnonymousIdentity` |
| Результат | Числовой итог одной сессии, отправленный через SDK |
| Рекорд | Лучший допустимый к публикации результат пользователя в конкретной игре и эпохе |
| Оценка | 1–5 звёзд за игру как продукт; с результатами не связана |
| Уровень доверия | Степень проверяемости результата, присваиваемая **платформой** |
| ★ Технический идентификатор (`id`) | Неизменяемый код игры из манифеста; основа хоста игрового домена |
| ★ Слаг (`slug`) | Публичный адрес игры на портале; локализуется, изменяем |
| ★ Хост игры (`host_label`) | DNS-метка игрового origin, производная от `id`; неизменяема |
| ★ Исходный пакет | Загруженный ZIP, хранится побайтово неизменно |
| ★ Рабочий бандл (runtime) | Исходный пакет с заменённым официальным SDK; только он публикуется |
| ★ Импорт | Автоматическое заполнение карточки игры данными манифеста и каталога |
| ★ Мастер добавления игры | Пошаговый сценарий CRM: загрузка → анализ → карточка → проверка → публикация |
| Владелец | Заказчик, работающий только через CRM |

**Вне объёма v1 (запрещено без отдельного соглашения):** общий рейтинг платформы, сезоны, турниры, соцсеть, чаты, комментарии, подписки, платежи, покупки, мобильные приложения, достижения, реальные призы, уровень `server_authoritative`, внешние сетевые домены в играх, `SharedArrayBuffer`, WASM-threads. Схема БД допускает добавление достижений в v2 **аддитивно**.

**Нормативные слова:** «должен/обязательно» — проверяемое требование; «рекомендуется» — отклонение фиксируется письменно; «запрещено» — блокирующее нарушение.

## §2.1. Концепция и продуктовые цели

Аудитория — офисные сотрудники и люди, желающие скоротать перерыв. Запуск в браузере без установки; регистрация не обязательна. Значительная доля пользователей приходит с общих корпоративных IP: лимиты только по IP недопустимы как основной механизм (§2.20, Приложение E).

| Метрика (после запуска, не приёмочная) | Цель |
|---|---|
| Медиана длительности партии | 5–30 мин |
| Медиана времени на сайте за визит | 30–40 мин |
| Доля визитов с ≥2 играми | ≥35 % |
| Отказ на странице игры | ≤45 % |
| Конверсия гость → регистрация | ≥3 % |
| ★ Время добавления игры владельцем (ZIP готов) | ≤15 мин, без разработчика |

## §2.2. Инварианты продукта

1. Все опубликованные игры доступны без регистрации.
2. Гости играют без ограничений по контенту; их результаты не попадают в рекорды и **никогда** не переносятся в аккаунт.
3. У каждой игры одна постоянная таблица рекордов за всё время (в рамках текущей эпохи, §2.11.4). Общего рейтинга платформы нет.
4. Оценка игры и рекорд — независимые подсистемы.
5. У игры один обязательный основной жанр, необязательные дополнительные жанры и теги.
6. Email при регистрации необязателен; подтверждённый email — единственный способ самостоятельного восстановления пароля.
7. Владелец управляет контентом, играми, жанрами, оценками, переводами, дизайном и SEO через CRM без изменения кода и деплоя.
8. Падение отдельной игры не влияет на работоспособность портала.
9. Язык игры всегда равен языку сайта; при отсутствии локали — резервный язык и бейдж покрытия.
10. ★ Добавление и обновление игры выполняется загрузкой ZIP; повторный ручной ввод данных, уже присутствующих в пакете, запрещён.
11. ★ `id` и `host_label` неизменяемы с момента первой публикации и не переиспользуются после удаления игры.

**Жизненный цикл:** переход на Django 6.2 LTS в течение 3 месяцев после выхода; CI с этапа 1 прогоняет 6.x в неблокирующем режиме.

## §2.4. Архитектура и домены

```
Пользователь → Nginx (TLS, rate limit, статика)
├── example.com ................. Django: портал + CRM + API (same-origin)
│      ├── PostgreSQL 18
│      ├── Redis cache / Redis broker → Celery worker + Beat
│      └── S3 (исходные пакеты / рабочие бандлы / медиа) ── CDN
└── <host_label>.example-games.net ... только статика игрового бандла
```

| Назначение | Адрес | Требования |
|---|---|---|
| Портал | `example.com` | Сайт, CRM, API `/api/v1/` |
| Игры | отдельный регистрируемый домен `example-games.net` | Не поддомен портала; cookies запрещены; `X-Robots-Tag: noindex` |
| Каждая игра | `<host_label>.example-games.net` | Свой origin; wildcard-DNS + wildcard-TLS (DNS-01) |
| Staging | `staging.example.com` | Basic auth + IP-allowlist, `noindex`, отдельные секреты, почтовый sandbox |

**Запрещено:** игры на поддомене портала; `SESSION_COOKIE_DOMAIN`/`CSRF_COOKIE_DOMAIN` с ведущей точкой; общий origin для разных игр; изоляция портами вместо доменов.

**Домены разработки:** `portal.test`, `<host_label>.games.test` → `127.0.0.1`, TLS mkcert, порт **8443**, Django — 8000. Порт 80 занят системным nginx.

### §2.4.1. ★ Идентификация игры: `id`, `slug`, `host_label`

| Понятие | Источник | Правила | Изменяемость |
|---|---|---|---|
| `Game.technical_id` | `manifest.id` | `^[a-z][a-z0-9_]{1,38}[a-z0-9]$` (3–40 символов, начинается буквой, заканчивается буквой или цифрой); глобально уникален, включая архивные и удалённые игры | Никогда |
| `Game.host_label` | Вычисляется платформой | `technical_id.replace("_", "-")`; длина ≤63; не входит в список зарезервированных меток; не начинается с `xn--` | Никогда |
| `Game.slug` | `catalog/en.json → name`, транслитерация/slugify | Канонический слаг портала; редактируется в CRM; при смене — `301` | Да |
| `GameTranslation.slug` | CRM / импорт | Уникален в рамках языка; при смене — `301` | Да |

Нормативные следствия:

1. Хост **никогда** не выводится из `slug`: смена названия, языка или слага не меняет origin игры, кеши и изоляцию.
2. Отображение `_ → -` инъективно (символ `-` в `id` запрещён), коллизии хостов между разными `id` невозможны; уникальность всё равно проверяется constraint'ом.
3. Зарезервированные метки (отказ валидации `V_HOST_RESERVED`): `www, mail, smtp, imap, pop, ftp, ns1, ns2, dns, api, cdn, assets, static, media, admin, crm, portal, games, game, staging, stage, dev, test, demo, preview, sandbox, vpn, proxy, auth, login, account, support, help, blog, shop, status, metrics, grafana, sentry, backup, s3, _dmarc, autodiscover, autoconfig`. Список расширяется в CRM без деплоя.
4. `id`, оканчивающийся на `_`, отклоняется (`V_ID_FORMAT`): иначе получается недопустимая DNS-метка с завершающим дефисом.
5. Загрузка ZIP, у которого `manifest.id` ≠ `technical_id` карточки, отклоняется (`V_ID_MISMATCH`); CRM предлагает создать новую карточку.
6. Удаление игры переводит её в `archived`; `technical_id` и `host_label` остаются занятыми навсегда.

### §2.4.2. Раздача игрового контента

Исходные пакеты — приватный бакет S3; рабочие бандлы — публичная раздача через CDN или Nginx-прокси. HTTPS на кастомном домене обязателен, «голый» S3 website-endpoint запрещён. Путь версии неизменяем: `/v/<runtime_hash-12>/index.html`.

Заголовки: ассеты — `public, max-age=31536000, immutable`; `index.html` — `no-cache`; `X-Content-Type-Options: nosniff`; корректные MIME. Серверное исполнение кода на игровом домене запрещено.

**Обязательно:** на игровом хосте **не должно быть заголовка `X-Frame-Options`**. Изоляция обеспечивается только `Content-Security-Policy: frame-ancestors`. В Nginx — `add_header ... always` с явным переопределением унаследованных заголовков. Наличие `X-Frame-Options` — блокирующий дефект приёмки.

### §2.4.3. Эталонная разметка iframe

```html
<iframe
  src="https://<host_label>.example-games.net/v/<runtime_hash12>/index.html#p=https%3A%2F%2Fexample.com&s=<session_uuid>"
  sandbox="allow-scripts allow-same-origin"
  allow="fullscreen; autoplay; gamepad"
  allowfullscreen
  referrerpolicy="no-referrer"
  loading="lazy"
  title="Game: <name>"
  class="ba-player"></iframe>
```

`allow-pointer-lock` добавляется только при `capabilities.pointerLock=true`. Во фрагменте — только несекретные значения; билет в URL не попадает никогда. Комбинация `allow-scripts`+`allow-same-origin` допустима исключительно из-за различия origin игры и портала.

**Резервный режим** (wildcard недоступен): один хост + sandbox **без** `allow-same-origin` (opaque origin), хранилище только через SDK, на ассеты `Access-Control-Allow-Origin: *` без `Access-Control-Allow-Credentials`. Поэтому `capabilities.storage:"local"` в v1 запрещён.

## §2.5. Инфраструктура и эксплуатация

**Production:** 4 vCPU / 8 ГБ RAM / 160 ГБ NVMe, ЕС/ЕЭЗ, S3 ~100 ГБ, CDN перед играми и медиа. Единый хост — известная точка отказа v1; план масштабирования описывается в документации.
**Окружения:** Development (локально), Staging (закрыт, обезличенные данные), Production. Реальные персональные данные в тестовых средах запрещены.

**Сервисы Docker Compose:** `web`, `db`, `redis-cache`, `redis-broker`, `worker`, `beat`, `nginx`, `backup`, `restore-check`. Секреты вне Git, постоянные тома, `restart: unless-stopped`, healthcheck у каждого сервиса, `depends_on: condition: service_healthy`, лимиты ресурсов, непривилегированный UID.

```yaml
db:
  image: postgres:18
  volumes:
    - pgdata:/var/lib/postgresql        # НЕ /var/lib/postgresql/data
  shm_size: 256mb
```

### Профиль разработки `dev-lite` (3.8 GiB RAM)

| Компонент | dev-lite | staging / production |
|---|---|---|
| PostgreSQL 18 | `shared_buffers=256MB`, `max_connections=30`, `work_mem=4MB` | полная конфигурация |
| Redis | два контейнера по 64 МБ (cache LRU + broker noeviction) | два, объёмы больше |
| Django | `runserver`, порт 8000 | Gunicorn за Nginx |
| Celery | `--pool=solo --concurrency=1` | конкурентность по CPU |
| Beat | профиль `manual` | постоянный сервис |
| Nginx + TLS | обязателен, mkcert, порт 8443 | Let's Encrypt, 443 |
| CDN, Sentry, счётчик | выключены | включены |
| Playwright | `--workers=1`, chromium | полная матрица в CI |
| Бэкапы | дамп по требованию | WAL-архив, PITR |

Пиковое потребление ≈2.4 ГБ. **Объединять кеш и брокер Redis запрещено даже в dev.**

**Пул соединений:** при `OPTIONS={"pool": {"min_size": 2, "max_size": 8}}` параметр `CONN_MAX_AGE` **обязан быть 0**. Альтернатива (пул выключен): `CONN_MAX_AGE=60`, `CONN_HEALTH_CHECKS=True`. Одновременное использование обоих механизмов запрещено. Суммарный `max_size` всех процессов ≤ `max_connections` минус резерв 5.

**Секреты и доступ:** переменные окружения / Docker secrets; `.env.example` без значений; ротация в runbook. SSH только по ключам, fail2ban, автообновления безопасности, UFW (22/80/443), БД и Redis только во внутренней сети.

## §2.6. Информационная архитектура и URL

Все публичные URL имеют языковой префикс `/<lang>/` из активных языков БД.

| Раздел | URL |
|---|---|
| Главная | `/<lang>/` |
| Каталог | `/<lang>/games/` |
| Жанр | `/<lang>/genres/<slug>/` |
| Страница игры | `/<lang>/games/<slug>/` |
| Игровой экран | `/<lang>/games/<slug>/play/` |
| Таблица рекордов | `/<lang>/games/<slug>/leaderboard/` |
| Аутентификация | `/<lang>/auth/…` |
| Кабинет | `/<lang>/account/…` (noindex) |
| Правовые документы | `/<lang>/legal/<slug>/` |
| Статические страницы | `/<lang>/pages/<slug>/` |
| Жалоба | `/<lang>/report/<type>/<id>/` |
| CRM | отдельный поддомен либо непредсказуемый префикс; noindex, обязательный 2FA |

Корень `/` → `302` по `Accept-Language` с `Vary: Accept-Language`; `x-default` → `/en/`. Слаги локализуются; при смене — `301`. Пагинация `?page=N`, canonical на текущую страницу, `noindex,follow` глубже 5-й страницы. Смена слага не влияет на игровой хост (§2.4.1).

**Главная:** логотип, навигация, переключатель языка, вход/регистрация, приветственный блок, «Популярное», «Высоко оценённые», «Новое», жанры, подборка редакции, футер. Не более 6 контентных блоков.

## §2.7. Дизайн, доступность, бюджеты производительности

**Стиль:** современный игровой портал, дружелюбный, яркий без кричащности. Тёмная и светлая темы. Дизайн-токены — CSS-переменные во внешнем файле темы из CRM. Компоненты: карточка игры, кнопка, поле, таблица, модальное окно, тост, скелетон, ★ степпер мастера, ★ строка отчёта валидации, ★ дифф-строка импорта.

**CRM управляет только предопределённым набором токенов** (цвета, радиусы, тени, отступы, шрифтовые пары). Генерация произвольных Tailwind-классов на лету запрещена.

**Адаптивность:** 360/640/768/1024/1280/1536. Плеер использует `dvh`. Горизонтальная прокрутка запрещена при ширине ≥320 px.

## §2.8. Каталог: поиск, фильтры, сортировки, популярность

**Карточка игры:** обложка 16:9, название, описание ≤120 симв., основной жанр, средняя оценка + число оценок, показатель популярности, ориентировочное время партии, отметка мобильной поддержки, ★ бейдж покрытия локализации, кнопка «Играть». Все поля заполняются импортом (§2.14.4).

**Фильтры:** жанр (основной и дополнительные), теги (мультивыбор), мобильная поддержка, язык интерфейса игры (по `effective_languages`), длительность (≤5 / 5–15 / 15–30 / 30+ мин по `estimated_play_minutes`). Комбинируются, отражаются в URL, работают через HTMX.

**Поиск:** PostgreSQL FTS (`tsvector` по названию и описанию) + `pg_trgm` для опечаток; вес названия выше; минимум 2 символа; пустая выдача предлагает популярное. Конфигурация FTS берётся из `Language.fts_config`; при отсутствии штатной — `simple` + `unaccent` + `pg_trgm` с пометкой в CRM.

| Код | Правило | Вторичный ключ |
|---|---|---|
| `rating` | `WR` ↓ | число оценок ↓, `id` ↑ |
| `new` | `published_at` ↓ | `id` ↓ |
| `old` | `published_at` ↑ | `id` ↑ |
| `popular` | зачёты за 30 дней ↓ | WR ↓, `id` ↑ |
| `votes` | число оценок ↓ | WR ↓, `id` ↑ |

`published_at` фиксируется при первой публикации и не меняется при перепубликации и обновлении версии.

**Формула рейтинга:** `WR = (v/(v+m))*R + (m/(v+m))*C`, `m=20`, `C=3.5` (настройки CRM). Фактические `R` и `v` показываются без подмены. Блоки «Лучшие»/«Высоко оценённые» требуют `v ≥ m`. Пересчёт — по сигналу изменения голосов и ночной задачей.

### Зачёт популярности

Зачёт при завершении сессии (`finished`, `aborted`, `expired`), если серверная длительность ≥15 с **и `GameSession.mode ∈ {user, guest}`**. Сессии `preview` и `autotest`, а также результаты `is_test=true` не учитываются никогда.

```sql
INSERT INTO game_play_credit (game_id, subject_type, subject_id, last_credited_at)
VALUES (:game, :stype, :sid, now())
ON CONFLICT (game_id, subject_type, subject_id) DO UPDATE
SET last_credited_at = now()
WHERE game_play_credit.last_credited_at <= now() - interval '30 minutes'
RETURNING 1;
```

Если строка возвращена — инкремент `GameDailyStats.unique_sessions` за текущую дату UTC. Окно скользящее. Агрегат популярности = сумма за 30 дней, кеш Redis 15 мин. `GamePlayCredit` хранится 90 дней. 100 перезапусков за 10 минут дают ровно 1 зачёт.

**Жанры и теги:** канонические коды `arcade, puzzle, action, racing, simulator, strategy, sports, casual, logic, platformer`; переводятся, имеют слаги, порядок, SEO-поля, изображения. `puzzle` — сборка/сопоставление; `logic` — дедукция/планирование. Создание — только владельцем либо ★ автоматическое создание тега при импорте (§2.14.4).

## §2.9. Система оценок игр

1. Шкала 1–5, целые звёзды; показываются средняя (1 знак), число оценок, распределение.
2. Голосовать может зарегистрированный пользователь с суммарным **серверным** временем игры ≥ `Game.rating_min_playtime_seconds` (по умолчанию 120). Учитываются только сессии `mode ∈ {user}` и `is_test=false`.
3. `UNIQUE(game_id, user_id)`; изменение перезаписывает голос. Лимит: ≤1 изменение в 24 ч, ≤5 в 30 дней.
4. Оценки заблокированных аккаунтов исключаются автоматически, восстанавливаются при разблокировке. Ручная модерация — с причиной и записью в журнал.
5. Агрегат пересчитывается транзакционно, хранится денормализованно.
6. Антифрод: возраст аккаунта ≥1 ч, ≤20 оценок в сутки, серии с одного IP/подсети как **вторичный** сигнал, журнал подозрительной активности, очередь модерации.
7. Гость видит оценки; при попытке голосовать — предложение регистрации без блокировки контента.

`rating_min_playtime_seconds` (порог голосования, CRM) и `min_session_seconds` (минимальная партия, из манифеста) — разные сущности.

## §2.10. Аккаунты, гости, восстановление

### 2.10.1. Анонимная идентичность

| Аспект | Решение |
|---|---|
| Создание | При первом запросе, требующем субъекта; сервер генерирует UUIDv7 |
| Носитель | Cookie `ba_anon` на origin портала: host-only, `HttpOnly`, `Secure`, `SameSite=Lax` |
| Формат | Подписанное `django.signing` значение `v1:<uuid>:<issued_at>`, проверка HMAC на каждом запросе |
| Серверная запись | `AnonymousIdentity`: `token_hash`, `created_at`, `last_seen_at`, `expires_at` |
| Срок жизни | 90 дней скользящих; по истечении — новая идентичность, данные не переносятся |
| Подмена | Отклоняется, создаётся новая идентичность, событие в `SecurityEvent` |
| Очистка cookies | Новый гость; в интерфейсе явно: «прогресс гостя хранится в этом браузере» |
| Несколько браузеров | Разные гости; принятое ограничение документируется |
| Фингерпринтинг | Запрещён |
| Согласие на cookies | Не требуется: строго необходимая cookie (обоснование в политике) |
| Регистрация | Гостевые результаты, рекорды и хранилище **не переносятся** |

**Гость может:** смотреть каталог, искать, фильтровать, запускать все опубликованные игры, играть без ограничения времени, смотреть оценки и рекорды, пользоваться хранилищем игры. **Не может:** отправлять рекорды, голосовать.

### 2.10.2. Регистрация

Обязательны логин, пароль, никнейм; email необязателен.

| Поле | Правила |
|---|---|
| Логин | 3–30, `[a-z0-9_.-]`, unique `citext`, публично не показывается |
| Никнейм | 3–20, Unicode-буквы/цифры/`_`/одиночные пробелы; уникальность по confusables-скелетону |
| Пароль | ≥12 символов, проверка по утечкам (HIBP k-anonymity), не совпадает с логином/никнеймом/email |
| Email | необязателен, уникален, требует подтверждения |

**Нормализация никнейма:** NFKC → casefold → skeleton по таблице Unicode confusables; реализация чистым Python (`confusable_homoglyphs` либо вендоренная таблица), без PyICU. Хранится `nickname_skeleton` с уникальным индексом.
**Хеширование:** Argon2id (`argon2-cffi`), `memory_cost=65536 KiB`, `time_cost=3`, `parallelism=4`; автоапгрейд при входе. Проверяются запрещённые выражения и имперсонация.
При регистрации: чекбокс соглашения (фиксируется версия), ссылки на документы, подтверждение возраста 16+, предупреждение «Без подтверждённого email восстановить пароль будет невозможно». Маркетинговое согласие отдельно, по умолчанию выключено.

### 2.10.3. Email и восстановление

Подтверждение ссылкой (24 ч). Смена — подтверждение нового + уведомление на старый + повторная аутентификация. Восстановление: только подтверждённый email, ссылка одноразовая, **TTL 30 минут**, хранится как хеш/HMAC. Ответ формы нейтрален. Rate limiting по аккаунту (первично) и IP (вторично). Администратор пароли не видит и не восстанавливает.
Почта: транзакционный провайдер в ЕС, SPF/DKIM/DMARC, обработка bounce; при недоставляемом адресе подтверждение сбрасывается, пользователь предупреждается.

### 2.10.4. Кабинет

Никнейм (смена ≤1 раз в 30 дней, история сохраняется), email и статус, смена пароля с инвалидацией прочих сессий, язык, тема, история игр, личные рекорды и места, согласия, экспорт данных JSON, удаление аккаунта (повторная аутентификация → окно отмены 7 дней → необратимая анонимизация). Логин и email другим пользователям не показываются.

### 2.10.5. Удаление аккаунта и никнеймы

| Данные | Действие |
|---|---|
| `LeaderboardEntry` | удаляется из публичной выдачи и из таблицы |
| `GameResult` | `user_id = NULL`, остаётся в обезличенных агрегатах |
| `GameRatingVote` | удаляется, агрегат пересчитывается |
| `GameStorage`, `UserGamePlaytime` | удаляются |
| `UserProfile`, `EmailAddress`, `NicknameHistory` | plaintext никнеймов и email удаляются, остаётся `skeleton_hmac` |
| Резерв никнейма | `NicknameReservation`: HMAC-SHA256 скелетона отдельным секретом, без ссылки на пользователя и без plaintext, **24 месяца** |
| Персональные данные | исчезают из активных систем ≤30 дней, из бэкапов — по истечении их срока (30 дней) |

Правовое основание резерва — законный интерес (предотвращение имперсонации); подлежит подтверждению профильным юристом.

## §2.11. Таблицы рекордов

1. Одна постоянная таблица на игру в рамках текущей эпохи (§2.11.4).
2. **Одна строка на пользователя:** `UNIQUE(game_id, epoch, user_id)`. Все попытки — в `GameResults`.
3. Направление сортировки задаётся игрой (`higher_is_better` / `lower_is_better`). Тай-брейк: `achieved_at ASC`, затем `user_id ASC`.
4. Единицы: очки — целые с локальным разделением разрядов; время — миллисекунды, формат `mm:ss.SSS`.
5. Отображение: место, никнейм, результат, дата, бейдж уровня доверия. TOP-10 в игре, TOP-100 с пагинацией на странице, всегда — строка текущего пользователя.
6. Личный раздел: лучший результат, последние 20 попыток, дата рекорда, место.
7. Гости в таблицу не попадают. Рекорды не зависят от версии игры и сохраняются при обновлении.

### 2.11.1. Допустимость и пересчёт

Результат допустим, если одновременно: `user IS NOT NULL` AND `is_public` AND NOT `is_quarantined` AND NOT `is_test` AND `epoch = Game.leaderboard_epoch` AND (если `leaderboard_only_verified` — `trust_level ≥ heuristic_validated`).
Пересчёт `LeaderboardEntry` — **в той же транзакции** при: вставке результата; помещении/снятии карантина; изменении `is_public`; переключении `leaderboard_only_verified`; удалении аккаунта; смене эпохи. Ночная задача сверяет всю таблицу. Если лучший стал недопустим — подставляется следующий допустимый; если допустимых нет — строка удаляется.

### 2.11.2. Защита от гонок

```sql
INSERT INTO leaderboard_entry AS le (game_id, epoch, user_id, best_result_id, value, achieved_at, is_public, trust_level)
VALUES (...)
ON CONFLICT (game_id, epoch, user_id) DO UPDATE
SET best_result_id = EXCLUDED.best_result_id,
    value = EXCLUDED.value, achieved_at = EXCLUDED.achieved_at,
    is_public = EXCLUDED.is_public, trust_level = EXCLUDED.trust_level
WHERE (EXCLUDED.value, EXCLUDED.achieved_at) IS DISTINCT FROM (le.value, le.achieved_at)
  AND ( <better>(EXCLUDED.value, EXCLUDED.achieved_at, le.value, le.achieved_at) );
```

Приёмочный тест: 100 параллельных результатов одного пользователя не теряют лучший результат и не создают дубликатов.

### 2.11.3. Индексы

| Таблица | Индекс |
|---|---|
| `LeaderboardEntry` | `(game_id, epoch, value DESC, achieved_at ASC) WHERE is_public` |
| `LeaderboardEntry` | `(game_id, epoch, value ASC, achieved_at ASC) WHERE is_public` |
| `LeaderboardEntry` | `UNIQUE(game_id, epoch, user_id)` |
| `GameResult` | `(game_id, user_id, value DESC, achieved_at ASC) WHERE is_public AND NOT is_quarantined AND NOT is_test` |
| `GameResult` | зеркальный по `value ASC` с тем же предикатом |
| `GameResult` | `UNIQUE(session_id)`, `UNIQUE(session_id, idempotency_key)` |

Поле результата везде называется `value`. Частичный индекс строится только по полям собственной таблицы.

### 2.11.4. ★ Эпохи рекордов (смена правил счёта)

`Game.leaderboard_epoch` — целое, по умолчанию 1. Изменение `score.direction` или `score.schemaVersion` между версиями **блокирует публикацию** до явного решения владельца (step-up 2FA):

| Вариант | Действие |
|---|---|
| «Начать новую таблицу» | `leaderboard_epoch += 1`; прежние строки остаются в БД с прошлой эпохой, публично недоступны; в CRM доступен раздел «Архив рекордов» и экспорт CSV |
| «Отменить публикацию» | версия остаётся черновиком, текущая версия не меняется |

Удаление прежних результатов не производится. Откат на версию с иными правилами счёта требует того же решения. Все переключения эпох журналируются в `AdminAuditLog`.

## §2.12. Игровые сессии, билеты, протокол, античит

### 2.12.1. Состояния и параметры

`created → active → finished | expired | aborted`. Переход в `active` — только по активации билетом. Повторный вход в конечное состояние запрещён.

| Параметр | Значение |
|---|---|
| TTL билета | 60 с, одноразовый |
| Активация после создания | ≤5 мин |
| Idle-таймаут (без heartbeat) | 30 мин |
| Максимальная длительность | `limits.maxSessionSeconds`, ≤7200 с |
| Heartbeat | каждые 30 с при видимой вкладке + ★ обязательный финальный перед `submit` |
| Активных сессий на (субъект, игра) | ≤3 (под advisory-lock по паре) |
| ★ Режим сессии | `user`, `guest`, `preview`, `autotest`; выставляется **сервером**, клиентское значение игнорируется |
| ★ Служебные режимы | `preview`/`autotest` доступны только из CRM (2FA, роль ≥ редактор) либо служебного тестового аккаунта |

### 2.12.2. Поток запуска

1. Родитель: `POST /api/v1/sessions` (same-origin, cookie + CSRF) → `{session_id, ticket, expires_at}`.
2. Родитель создаёт iframe **без билета в URL**, хранит `session_id` и `binding_nonce` в памяти страницы.
3. SDK: `postMessage {type:"ba:hello", protocol:1, session_id}` с конкретным `targetOrigin` из `#p=`.
4. Родитель валидирует сообщение (§2.12.4), затем `POST /api/v1/sessions/{id}/activate` с билетом.
5. Сервер гасит билет, переводит сессию в `active`, возвращает публичный контекст.
6. Родитель передаёт контекст: язык, режим, никнейм, правила счёта, лимиты, объединённые локали, уровень доверия, seed.

Игра не получает билет, cookies портала, email, логин, токены. Перезагрузка iframe → новая сессия.

### 2.12.3. Серверное время игры

```
credited_delta = clamp(now - last_heartbeat_at, 0, 45 s)
при первом heartbeat: clamp(now - activated_at, 0, 45 s)
GameSession.credited_ms += credited_delta
UserGamePlaytime.verified_seconds += credited_delta / 1000   # только mode=user, is_test=false
```

Heartbeat отправляется только при `document.visibilityState === 'visible'`. Разрывы >45 с не засчитываются. Серверная длительность = `credited_ms`, capped `maxSessionSeconds`. Клиентское время — вспомогательное.

★ **Допуск правдоподобия длительности** (устраняет ложные отказы):

```
accepted  ⟺  |duration_ms − credited_ms| ≤ 5000
             AND duration_ms ≤ maxSessionSeconds*1000
             AND (is_test OR duration_ms ≥ min_session_seconds*1000)
```

SDK обязан отправить финальный heartbeat непосредственно перед `ba:submit`. Для `autotest` нижняя граница не применяется, верхняя ограничена 60 с.

### 2.12.4. Валидация postMessage

**Родитель обязан проверить, в указанном порядке:**
1. `event.source === iframe.contentWindow`;
2. `event.origin` точно равен ожидаемому origin игры из БД (схема + хост + порт);
3. `data.source === "ba-sdk"`, `data.protocol === 1`;
4. `data.type` входит в allowlist;
5. `data.sessionId` равен текущей сессии этого iframe;
6. `data.requestId` — UUID, не обрабатывался ранее (LRU на 512 значений);
7. соответствие JSON-схеме для данного типа;
8. счётчик ≤60 сообщений/мин на сессию;
9. состояние сессии допускает данный тип сообщения.

**SDK обязан проверить:** `event.source === window.parent`; `event.origin === parentOrigin` из фрагмента; `source === "ba-host"`; протокол; `sessionId`; корреляцию `requestId`; схему. Неизвестные и просроченные сообщения игнорируются молча.

| Случай | Поведение |
|---|---|
| Замена/удаление iframe | Сообщения игнорируются; сессия закрывается по idle-таймауту |
| `ba:newSession` | Старый `sessionId` инвалидируется, LRU `requestId` очищается, ★ возвращается новый контекст с новым seed |
| После `finished` | Принимаются только `ba:leaderboard`, `ba:storage`, `ba:newSession`, `ba:exit` |
| Копирование URL iframe | Родитель создаёт новую сессию; чужая сессия отклоняется проверкой владения |
| Две вкладки | Билет одноразовый: вторая активация → `E_TICKET_INVALID` |
| Таймауты | init 5 с, submit 10 с, чтение 5 с |

### 2.12.5. Отправка результата

SDK → родитель (`ba:submit`) → `POST /api/v1/sessions/{id}/result` с `Idempotency-Key` → ответ → SDK (`ba:result`). Прямые cross-origin запросы из iframe запрещены; CORS на API не открывается.

**Серверные проверки:** существование сессии; принадлежность субъекту; соответствие игре **и версии**; состояние `active`; срок; однократность завершения; формат и диапазон; правдоподобие длительности (§2.12.3); rate limit; стоп-листы; правила верификатора.

★ **Гость:** API отвечает `403 E_GUEST_FORBIDDEN`, **SDK нормализует ответ** в
`{status:"guest", code:"E_GUEST_FORBIDDEN", rank:null, isPersonalBest:false, isRecord:false, trustLevel:"client_reported"}`.
Ретраи для этого ответа **запрещены**; игра показывает результат и уведомление о несохранении. Результат гостя в БД не сохраняется.

**Идемпотентность:** `Idempotency-Key` уникален в рамках сессии, хранится бессрочно вместе с ответом. Повтор с тем же ключом в любой момент возвращает сохранённый ответ. Другой ключ для завершённой сессии → `E_SESSION_FINISHED`. SDK делает до 3 повторов с экспоненциальной задержкой (кроме `guest`, `E_VERIFY_FAILED`, `E_SCORE_RANGE`, `E_SESSION_EXPIRED` — они не ретраятся), показывая нейтральный статус «сохраняем…».

**PLAY AGAIN:** `ba.newSession()` → родитель создаёт сессию без перезагрузки iframe → возвращает новый контекст (новый `sessionId`, новый `seed`). Игра полностью сбрасывает состояние. Лимит ≤30 новых сессий в час на субъекта; при отказе игра остаётся на экране результатов с нейтральным сообщением.

### 2.12.6. Уровни доверия и верификаторы

| Уровень | Смысл | Доступность в v1 |
|---|---|---|
| `client_reported` | число из браузера, базовые эвристики | да |
| `heuristic_validated` | расширенные проверки диапазонов, времени, событий | да |
| `replay_verified` | лог событий + seed воспроизведён на сервере | да |
| `server_authoritative` | результат вычислен платформой | зарезервирован |

Уровень присваивает платформа; значение манифеста — заявка. Верификатор — Python-плагин в репозитории платформы: `verify(ctx) -> Verdict(accepted, level, flags, reason)`, назначается в CRM per game. Серверных компонентов у игры нет.
Эвристики работают всегда и ★ используют импортированный `verification.profile` (`maxPointsPerSecond`, `maxIdleGapMs`): границы очков, «очки/секунда», монотонность событий, привязка seed, частота попыток, выбросы распределения, IP/устройство как вторичный сигнал. Подозрительные результаты → карантин + очередь модерации + `SecurityEvents`. У каждой строки рекорда — бейдж уровня. Абсолютная защита от читов не заявляется.

### 2.12.7. Формат eventLog и реплей

```json
{"v":1,"seed":"<строка от платформы>","events":[{"t":0,"k":"start","d":{}},
{"t":1530,"k":"hit","d":{"x":12,"y":4}}]}
```

| Ограничение | Значение |
|---|---|
| Сериализация | канонический JSON (сортировка ключей, без пробелов), UTF-8, gzip |
| Размер | ≤256 КиБ сжатый, ≤2 МиБ распакованный |
| Число событий | ≤20 000 |
| `t` | целые мс от старта, монотонно неубывает, ≤ `duration_ms + 1000` |
| `k` | код из словаря, объявленного в манифесте |
| Схема | `verification.eventSchema` (JSON Schema 2020-12), проверяется до реплея |

Реплей: детерминированный движок на платформе, тот же seed, таймаут 5 с, память ≤256 МиБ, без сети и файловой системы. Расхождение → карантин, уровень не повышается, пользователю — нейтральное сообщение.

## §2.13. Игровой экран и экран результатов

Страница `/play/`: плеер, «Пауза», «Заново», «На весь экран», «Выйти к игре», индикатор загрузки, обработка ошибок (таймаут 15 с → сообщение + «Повторить» + ссылка на страницу игры), строка состояния отправки.
Экран результатов реализует игра (`BA-GAME-2.2 §6`) в стилистике аркадных автоматов 1990-х по данным платформы: GAME OVER, результат, лучший личный, место, NEW HIGH SCORE (**только после `isRecord === true` от сервера**), TOP-10, «Играть снова», «Выйти». Никнейм подставляется автоматически.

### 2.13.1. Матрица отказов

| Ситуация | Поведение платформы | Поведение игры |
|---|---|---|
| Потеря сети во время партии | Индикатор, heartbeat буферизуется (≤3 подряд) | Пауза, сохранение состояния партии в памяти |
| Восстановление сети ≤ idle-таймаута | Сессия продолжается, сверх 45 с время не засчитывается | Возобновление |
| Потеря сети в момент отправки | — | 3 ретрая с тем же `Idempotency-Key`, статус «сохраняем…» |
| Отказ после 3 ретраев | Ответ недоступен | Нейтральное сообщение, кнопка «Повторить отправку», результат в памяти до `ba:newSession` |
| Истечение сессии | `E_SESSION_EXPIRED` | Понятное сообщение, предложение новой партии, без ретраев |
| Отказ верификатора | `E_VERIFY_FAILED`, карантин | Нейтральный текст без обвинений и кодов, без ретраев |
| ★ Гость | `403 E_GUEST_FORBIDDEN` → SDK `status:"guest"` | Результат показан полностью, строка «Результат не сохраняется», приглашение регистрации, **без ретраев** |
| Потеря фокуса | — | Пауза при `limits.pauseOnBlur`, звук выключен |

**Потеря результата после 20-минутной партии из-за кратковременного сбоя сети недопустима.**

## §2.14. ★ Пайплайн игровых пакетов: импорт, мастер, версии

### 2.14.1. Сущности пайплайна

`GameImportDraft` (черновик мастера) → `GameVersion` (неизменяемая версия) → `Game.current_version` (единственный источник истины о текущей версии). Поле `GameVersion.is_current` отсутствует.

Хранение: исходный ZIP (`package_hash`, приватный бакет, побайтово неизменен) и рабочий бандл (`runtime_hash`, публичная раздача). Оба доступны для скачивания в CRM.

### 2.14.2. Валидация ZIP (пороги — константы)

| Проверка | Порог |
|---|---|
| Размер ZIP | ≤25 МБ (рекомендуется ≤8 МБ) |
| Распакованный объём | ≤100 МБ |
| Коэффициент сжатия | ≤100:1 |
| Число файлов | ≤2000 |
| Размер файла | ≤20 МБ |
| Критический путь (measured, после инъекции SDK) | ≤2 МБ gzip — предупреждение; >4 МБ — отказ |
| Пути | только относительные, без `..`, без абсолютных, без symlink, без коллизий имён |
| Расширения | `html, css, js, mjs, json, png, jpg, jpeg, webp, avif, gif, svg, woff2, mp3, ogg, wav, wasm, txt, md` |
| Служебные файлы | `.git`, `.DS_Store`, `__MACOSX`, `node_modules`, `*.map` — отклоняются |
| Кодировка/переводы строк | UTF-8 без BOM, LF |
| Манифест | JSON Schema `BA-GAME-2.2 §4` |
| Каталог | JSON Schema `BA-GAME-2.2 §11`, все заявленные языки |
| Локали | все заявленные языки + `en`, паритет ключей |
| Внешние ссылки | статический скан; `capabilities.externalOrigins` непуст → отказ |
| Запрещённые API | `eval`, `new Function`, строковые таймеры, `serviceWorker`, `document.cookie`, `window.top`, `parent.location`, `SharedArrayBuffer`, геолокация/камера/микрофон/платежи/уведомления, `alert/confirm/prompt` |
| Обложка/скриншоты | реальные размеры 1280×720, ≤200/300 КБ |
| Хеш | SHA-256 пакета и каждого файла |

Распаковка — в изолированном временном каталоге с квотой, вне веб-корня, без прав на исполнение. Отчёт построчный, с файлом и причиной (§2.14.7). Статический скан JS **не гарантирует** обнаружения вредоносного поведения — **ручная проверка первой версии каждой игры обязательна и не может быть отменена**.

Идемпотентность: если `package_hash` уже загружен в эту карточку, новая версия не создаётся; CRM показывает существующую версию и её отчёты.

### 2.14.3. Инъекция SDK и рабочий бандл

1. Платформа **всегда** заменяет `js/ba-sdk.js` официальной реализацией, совместимой с `manifest.sdkVersion` (semver-range) и `manifest.protocol`. Содержимое файла из пакета не исполняется и не анализируется на «доверенность»: заглушка и «официальный» файл из пакета равнозначны и равнозначно заменяются.
2. Если совместимой официальной версии нет → отказ `V_SDK_INCOMPATIBLE` с указанием требуемого диапазона и доступных версий.
3. Формируется рабочий бандл: копия дерева файлов с единственным изменённым файлом. Вычисляются `runtime_hash` и хеши каждого файла. Путь публикации `/v/<runtime_hash[:12]>/`; при коллизии префикса длина увеличивается до 16.
4. Формируется **отчёт инъекции**: путь файла, хеш и размер «до/после», версия SDK, версия контракта. Прикладывается к отчёту валидации.
5. Пересчитывается **фактический критический путь**: gzip-сумма файлов `assets.critical`, обязательный минимум — `index.html`, `css/style.css`, `js/ba-sdk.js`, `js/game.js`, `js/rng.js`, `locales/<defaultLanguage>.json`, шрифты и графика первого экрана. Расхождение с заявленным `criticalPathBytes` >10 % — предупреждение; фактическое значение всегда приоритетно.
6. Предпросмотр, автотест и публикация выполняются **только на рабочем бандле**.
7. CSP игрового хоста формируется по `capabilities`: `'wasm-unsafe-eval'` добавляется только при `wasm:true`; sandbox — `allow-pointer-lock` только при `pointerLock:true`.
8. Исходный ZIP остаётся побайтово неизменным и доступным для скачивания и повторной сборки бандла (например, при выпуске SDK 1.1.x).

### 2.14.4. Импорт данных в карточку

Полный контракт полей — **Приложение J**. Нормативные правила:

1. Первая загрузка ZIP **автоматически создаёт карточку** и заполняет все импортируемые поля: название, короткое и полное описание, инструкции, управление, SEO, обложку, скриншоты, alt-тексты, жанр, теги, языки, ориентацию, мобильную поддержку, длительность, акцентный цвет, правила счёта, лимиты, кредиты.
2. Ручной ввод обязателен только для того, чего нет в пакете: статус публикации, расписание, настройки доверия и верификатора, порог голосования, подборки, права. Заставлять владельца повторно вводить данные из ZIP запрещено.
3. Неизвестный код жанра → отказ `V_GENRE_UNKNOWN`. Неизвестный тег → создаётся автоматически (`code` = значение из манифеста), `TagTranslation.name` = код, помечается «требует перевода» и попадает в отчёт импорта как предупреждение.
4. Неизвестный код языка (отсутствует в `Language`) → отказ `V_LANG_UNKNOWN`.
5. Изображения импортируются в `GameAsset` с типом, порядком и alt из каталога; конвертация в WebP/AVIF и генерация `srcset` — задачей Celery.
6. **Повторный импорт (новая версия в существующей карточке):** поля без флага `overridden` обновляются автоматически; поля с флагом сохраняют значение CRM и показываются в диффе как конфликт с выбором «Принять из пакета» / «Оставить как есть». Все решения журналируются.
7. Владелец может снять флаг («Вернуть значение из пакета») для любого поля.
8. Итоговый отчёт импорта показывает: создано/обновлено/пропущено/конфликты, по каждому полю — источник и прежнее значение.

### 2.14.5. Мастер добавления игры (CRM)

Кнопка **«Добавить игру»** в разделе «Игры». Пять шагов, состояние на сервере (`GameImportDraft`), автосохранение, возврат к любому шагу, сохранение черновика на любом шаге.

| Шаг | Содержание | Блокирующие условия перехода |
|---|---|---|
| 1. Загрузка | Drag&drop или выбор файла, ZIP ≤25 МБ, прогресс, проверка дубликата по хешу | Файл не ZIP, превышение размера, повторная загрузка того же хеша |
| 2. Анализ | Построчный отчёт: структура, манифест, SDK, графика, переводы, жанр/теги, безопасность, бюджеты; кнопка «Скачать отчёт» | Любая ошибка severity `blocker` |
| 3. Карточка | Предзаполненные поля, обложка и скриншоты, языки и % покрытия, характеристики, правила счёта, SEO; при обновлении — дифф с пакета | Не заполнены обязательные поля CRM; неразрешённые конфликты диффа |
| 4. Проверка | Предпросмотр «Компьютер» (1280×720) и «Телефон» (360×640) в песочнице на рабочем бандле; кнопка «Запустить автотест»; отчёт Playwright; чек-лист ручной проверки первой версии с указанием проверяющего | Красный автотест; отсутствие отметки ручной проверки для первой версии |
| 5. Публикация | «Опубликовать сейчас» / «Запланировать» (`publish_at`) / «Сохранить черновик»; step-up 2FA; предупреждения о смене правил счёта (§2.11.4) | Не решён вопрос эпохи рекордов; истёк step-up |

Предпросмотр и автотест создаются в режимах `preview`/`autotest` и не влияют на статистику, популярность, время игры и рекорды (§2.8, §2.9, §2.12.1).

### 2.14.6. Обновление существующей игры

Сценарий: карточка игры → вкладка «Игровой пакет» → «Загрузить новую версию» → тот же мастер (шаги 2–5) в режиме обновления.

Гарантии:
1. `manifest.id` обязан совпадать с `technical_id` карточки, иначе отказ `V_ID_MISMATCH`.
2. `manifest.version` уникален в рамках игры; при значении ниже текущего — предупреждение (не отказ).
3. Рекорды, оценки, статистика, хранилище игроков, слаги, SEO-настройки и подборки **сохраняются**.
4. История версий сохраняется полностью; откат — переключение `Game.current_version` одной операцией (атомарно, с инвалидацией кеша сменой хеш-пути).
5. Смена `score.direction` или `score.schemaVersion` → процедура §2.11.4 до публикации.
6. Изменение `supportedLanguages` допускается; удалённые языки помечаются в отчёте, покрытие пересчитывается.
7. `GameStorage` между версиями сохраняется; игра обязана версионировать собственные ключи (`save.v1`, `settings.v1`) и корректно читать данные прежних версий.
8. `published_at` не изменяется.

### 2.14.7. Диагностика и отчёт валидации

Отчёт — структурированный JSON + человекочитаемый Markdown, обе версии доступны кнопкой «Скачать отчёт». Каждая запись:

```json
{"code":"V_LOCALE_PARITY","severity":"blocker","file":"locales/de.json",
 "message":"Отсутствуют ключи: resume, exit","hint":"Добавьте недостающие ключи во все заявленные локали.",
 "meta":{"missing":["resume","exit"]}}
```

`severity ∈ {blocker, warning, info}`. CRM показывает список с фильтром «только блокирующие», ссылкой на файл и подсказкой по исправлению; сообщения локализованы на языке интерфейса CRM. Технические коды показываются рядом с текстом (для передачи разработчику игры), но не заменяют текст. Полный словарь кодов — **Приложение K**. Отчёты хранятся в `GameVersion.validation_report`, `import_report`, `e2e_report`.

### 2.14.8. Автотест игры в CRM

Playwright headless на рабочем бандле проверяет: запуск в песочнице; инициализацию SDK; отсутствие ошибок консоли; все заявленные языки; самостоятельное завершение в режиме `autotest` ≤25 с и отправку результата в границах; корректную реакцию на `autotest:finish`; гостевой сценарий (результат показан, ретраев нет); размеры 360×640 и 1280×720 без обрезки и горизонтальной прокрутки; отсутствие `X-Frame-Options`; отсутствие обращений к данным портала; отсутствие внешних сетевых запросов; фактический критический путь.
Отчёт прикладывается к версии. Без зелёного отчёта публикация блокируется (форсирование владельцем — с письменным подтверждением риска и записью в журнал).

### 2.14.9. Публикация, планирование, откат

Загрузка → валидация → карантин → предпросмотр → публикация (вручную или по `publish_at`, задача Celery, отмена до момента публикации). Версии неизменяемы. Откат = переключение `Game.current_version`. Кеш сбрасывается сменой хеш-пути. Статусы игры: `draft / review / published / hidden / archived`.

## §2.15. Мультиязычность

**Языки:** активные языки БД (стартовый набор `en, de, nl, ru, fr, es`), резервный `en`. Добавление языка — владельцем в CRM без изменения кода и деплоя.

### Архитектура

* Контентные переводы — таблицы переводов с FK на `Language`.
* Строки интерфейса — `TranslationEntry` (namespace + key + язык + значение + статус), кеш Redis, шаблонный тег; отсутствие перевода → резервный язык; ключ **никогда не показывается**, факт логируется.
* Плюрализация по CLDR (Babel), плейсхолдеры ICU MessageFormat.
* Строки Django/сторонних пакетов остаются на gettext; в интерфейсе портала их быть не должно.
* Языковой префикс URL, sitemap и middleware читают один источник — активные языки БД.

### Процедура добавления языка

| Шаг | Требование | Блокирующий |
|---|---|---|
| 1 | `Language`: code, name, is_rtl, sort_order, plural_rule, fts_config | да |
| 2 | **100 % строк интерфейса портала переведено и опубликовано** | да |
| 3 | `fts_config`: штатная конфигурация PG либо `simple` + `unaccent` + `pg_trgm` с пометкой | нет |
| 4 | URL-префикс, sitemap, hreflang, `x-default` — автоматически | авто |
| 5 | Переводы контента; при отсутствии — fallback `en` + бейдж | нет |
| 6 | Игровые локали; при отсутствии — бейдж покрытия, исключение из подборок «Лучшие» для этого языка | нет |
| 7 | Шрифты и глифы, проверка длинных строк (+35 %), RTL при `is_rtl` | да |

### ★ Языки игры и языки сайта

1. Список языков SDK **не ограничен шестью кодами**: `context.language` — строка; игра обязана корректно работать при любом коде, откатываясь на `fallbackLanguage`, затем на встроенную копию `en`.
2. Игра объявляет `supportedLanguages` ⊆ активных языков сайта; обязательны `defaultLanguage` и `en`. Для заявленных языков обязателен паритет ключей локалей и полный набор каталожных файлов.
3. `Game.effective_languages` = языки пакета ∪ языки, для которых CRM-override покрывает **100 % ключей** игрового словаря. Такой язык добавляется без нового ZIP.
4. Покрытие = `|effective_languages ∩ активные языки| / |активные языки|`; в CRM — процент и список отсутствующих языков; на карточке — бейдж «Полная локализация» / «Частичная: N из M».
5. Язык игры всегда равен языку сайта; при отсутствии — резервный язык игры, затем `en`.
6. Итоговый словарь = `locales/<lang>.json` пакета + `GameLocaleOverride` из CRM (приоритет у CRM); собирается сервером, кешируется с ETag, передаётся через SDK. Правка текста игры не требует нового ZIP.

**Переключение:** переключатель в шапке, первичное предложение по `Accept-Language` (не по IP), сохранение в профиле и cookie `lang`, принудительная смена запрещена.
**CRM переводов:** редактор с фильтрами статусов (`не переведено / черновик / на проверке / проверено / опубликовано`), импорт/экспорт CSV и JSON, машинный черновой перевод с обязательной пометкой, процент готовности, предпросмотр, проверка плейсхолдеров. Значения рендерятся как текст, HTML запрещён.

## §2.18. Статистика

**Внутренняя, без идентификаторов на устройстве:** просмотры, уникальные посетители (суточный агрегат по серверной сессии без фингерпринтинга), запуски, завершения, доля завершений, популярность (§2.8), средние оценки, активность по часам, воронка гость→регистрация. Сырые события 90 дней, далее агрегаты.
★ Сессии и результаты `preview`/`autotest`/`is_test` исключаются из всех продуктовых агрегатов и учитываются только в служебном разделе «Проверки версий».

**Партиционирование:** `AnalyticsEvent` — RANGE по `created_at`, помесячно, PK `(id, created_at)`. Celery создаёт партиции на 3 месяца вперёд, выполняет `DETACH` + `DROP` старше 90 дней.
**Внешний счётчик:** место в футере, подключение в CRM только после согласия, через изолированный iframe или проверенный HTTPS-скрипт с ограничением CSP.

В CRM — диагностика (пустые описания, дубли Title, отсутствующие alt, битые ссылки, непереведённые строки) и поля верификации Google Search Console и Bing Webmaster Tools.

## §2.20. Безопасность

### Заголовки портала (production)

```
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-<random>';
  style-src 'self'; img-src 'self' data: https://cdn.example.com;
  font-src 'self'; connect-src 'self'; frame-src https://*.example-games.net;
  frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()
Cross-Origin-Opener-Policy: same-origin
X-Frame-Options: DENY
```

**Dev-отличия:** HSTS выключен (`SECURE_HSTS_SECONDS=0`, без preload), `frame-src https://*.games.test:8443`. `style-src 'self'` без nonce: палитра приходит внешним файлом `/theme-<hash>.css`.

### Заголовки игрового хоста

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval';
  style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:;
  font-src 'self' data:; connect-src 'self'; worker-src 'self' blob:;
  frame-ancestors https://example.com; form-action 'none'; object-src 'none'; base-uri 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
X-Robots-Tag: noindex, nofollow
Cross-Origin-Resource-Policy: cross-origin
Permissions-Policy: fullscreen=(self), gamepad=(self), autoplay=(self)
# X-Frame-Options ОТСУТСТВУЕТ — обязательно
```

`'wasm-unsafe-eval'` — только для игр с `capabilities.wasm=true`; `'unsafe-eval'` запрещён. Cookies на игровом домене не выставляются никогда. В dev `frame-ancestors https://portal.test:8443`.

### Прикладной уровень

CSRF на всех изменяющих запросах (включая гостевые и загрузку ZIP); автоэкранирование, запрет `|safe` для пользовательских данных; ORM без сырого SQL с интерполяцией; Argon2id + проверка утечек; ротация сессии при входе; `SESSION_COOKIE_HTTPONLY/SECURE=True`, `SAMESITE=Lax`, host-only; инвалидация сессий при смене пароля; ролевой доступ и 2FA персонала; журнал безопасности; Sentry без PII; обновление зависимостей и скан уязвимостей в CI.

### Изоляция игр

Отдельный домен и origin на игру; точный sandbox и `allow`; CSP выше; сеть только `'self'`; запрет доступа к данным портала; полная валидация сообщений; лимит 60 сообщений/мин на сессию; таймауты.

### Rate limiting и NAT

Основной ключ лимита — **субъект**. IP — вторичный сигнал с повышенными порогами и **прогрессивной проверкой** (challenge) вместо жёсткого отказа. IPv6 агрегируется по /64. Полная таблица — Приложение E.

### Загрузка контента

Пороги §2.14.2, карантин, отсутствие исполнения на игровом домене, санитизация SVG, обязательная ручная проверка первой версии каждой игры, ★ распаковка вне веб-корня с квотой и таймаутом задачи.

Сессии авторизации — стандартный `django_session`. Достижения — вне v1, добавляются аддитивно.

## §2.23. API платформы

Префикс `/api/v1/`, same-origin, `SessionAuthentication` + CSRF, JSON, DRF-throttling. CORS не открывается. Гостевые запросы авторизуются связкой `ba_anon` + `csrftoken` + активная игровая сессия; передача идентификатора субъекта в теле запрещена и игнорируется.

## §2.24. Наблюдаемость

Sentry (ЕС) с релизами и source maps; JSON-логи с request-id; метрики (RPS, латентность, 5xx, очередь Celery, соединения БД и пул, кеш-hit, диск, память, ★ длительность и доля отказов валидации ZIP, ★ длительность автотестов); uptime каждые 60 с; алерты: недоступность, 5xx выше порога, очередь > N, диск > 80 %, сертификат < 14 дней, сбой бэкапа, отсутствие heartbeat-задач, рост карантина результатов. Автопродление Let's Encrypt с проверкой и reload Nginx. Регламент релиза: тег → CI → образ → обратно совместимые миграции → деплой → smoke-тест → откат одной командой.

# ДОКУМЕНТ 2 — BA-GAME-2.2 (полный, заменяет 2.0 и дельту 2.1)

**Совместим с:** `BA-PLAT-4.2`, `BA-SDK-1.1`, протокол 1.
**Назначение:** самодостаточное задание для разработчика (в том числе ИИ) браузерной игры-«картриджа». Нумерация сквозная §1–§17; ссылки на прежние §3.x не применяются.

## §1. Что вернуть

Ты — разработчик браузерных игр. Ты создаёшь **готовый игровой картридж**: один ZIP-архив, который владелец портала загружает в CRM, и игра сразу работает. Владелец не программист: он не будет ничего дописывать, собирать, компилировать или настраивать. Всё необходимое — внутри архива.

1. Файл `<id>-<version>.zip` со структурой из §3.
2. Текстом в ответе: `manifest.json`, отчёт самопроверки (§15), перечень отклонений (§16).
3. Если приложить ZIP технически невозможно — выведи **полное содержимое каждого файла** без сокращений и многоточий, плюс `pack.py` (Python 3, только стандартная библиотека), собирающий корректный ZIP.

Запрещены макет, заготовка, псевдокод, `// TODO`, «здесь добавьте логику», незаполненные ассеты, демонстрационный каркас. Игра играбельна от первого кадра до экрана результатов.

★ CRM автоматически создаёт карточку игры из твоих `manifest.json` и `catalog/*.json`. Всё, что ты не заполнишь, придётся вводить владельцу вручную — это дефект картриджа.

## §2. Технические основы

* Чистые HTML5 + CSS3 + JavaScript ES2022. **Классические скрипты** (`<script defer src=...>`), без ES-модулей, сборщиков, npm, TypeScript, транспиляции.
* Рендер: Canvas 2D (предпочтительно) либо WebGL2. Phaser разрешён, только если готовый минифицированный файл лежит внутри пакета и имеет совместимую лицензию.
* Никаких сетевых запросов, кроме загрузки собственных файлов пакета — **только относительными путями**.
* Игра работает внутри `<iframe>` на отдельном домене, по пути вида `/v/<hash>/`, в песочнице `sandbox="allow-scripts allow-same-origin"` (при `pointerLock` добавляется `allow-pointer-lock`), с CSP:
  `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:; font-src 'self' data:; connect-src 'self'; worker-src 'self' blob:; form-action 'none'; object-src 'none'; base-uri 'self'`.
  При `capabilities.wasm: true` платформа добавляет `'wasm-unsafe-eval'`.
* ★ Игра обязана работать и в резервном режиме **opaque origin** (sandbox без `allow-same-origin`): без `localStorage`, `sessionStorage`, `IndexedDB`, `document.cookie`. Всё сохранение — через `ba.storage`.
* ★ Тег `<base>` запрещён. Игра не знает и не должна знать домен портала, идентификаторы пользователя, cookies.


Правила полей:

* `id` — `^[a-z][a-z0-9_]{1,38}[a-z0-9]$`: 3–40 символов, начинается буквой, заканчивается буквой или цифрой, только `[a-z0-9_]`. Никогда не меняется. ★ Платформа строит из него адрес игрового домена заменой `_` на `-`, поэтому завершающее подчёркивание запрещено, а метки вроде `admin`, `api`, `www`, `staging` использовать нельзя. Публичный адрес страницы игры (слаг) платформа создаёт сама из названия — придумывать его не нужно.
* `version` — semver; при обновлении игры увеличивается, `id` остаётся прежним.
* `sdkVersion` — semver-range совместимости (`"^1.0"`), `protocol` — `1`.
* `genre` — ровно один из: `arcade, puzzle, action, racing, simulator, strategy, sports, casual, logic, platformer`. `puzzle` — сборка/сопоставление; `logic` — дедукция/планирование.
* `tags` — до 8, английские слова в нижнем регистре.
* `supportedLanguages` — заявленные языки; обязательны `defaultLanguage` и `en`. Стартовый набор портала: `en, de, nl, ru, fr, es`.
* `score.maxValue` обязателен, `null` запрещён. `score.unit` — `points|ms|items|errors`. `schemaVersion` увеличивается только при изменении смысла очков.
* `limits.minPlaytimeSeconds` ≥ 5 (минимальная партия, не порог голосования), `maxSessionSeconds` ≤ 7200.
* `capabilities.externalOrigins` — **всегда пустой массив**; `capabilities.storage` — **только `"sdk"`**.
* `leaderboard.claimedVerification` — `client_reported | heuristic_validated | replay_verified`. Не завышай: `replay_verified` допустим только если вся логика детерминирована от seed, и тогда `verification.eventSchema` и `eventKinds` обязательны. Уровень присваивает платформа, манифест — заявка.
* `assets.critical` — точный перечень файлов до первого игрового кадра, **обязательно включая** `index.html`, `css/style.css`, `js/ba-sdk.js`, `js/rng.js`, `js/game.js`, `locales/<defaultLanguage>.json`, шрифты и графику первого экрана. Суммарный gzip ≤2 МБ; платформа пересчитывает фактическое значение после подмены SDK. Остальное грузится лениво.
* `theme.accent` — акцентный цвет карточки в каталоге.
* `credits` — автор, лицензия, признак ИИ-происхождения по каждому материалу.

## §6. SDK — единственный способ связи с порталом

Файл `js/ba-sdk.js` подключается первым: `<script defer src="js/ba-sdk.js"></script>`.
★ Платформа **всегда** заменяет этот файл официальной реализацией при публикации; исходный ZIP сохраняется неизменным. Поэтому:

* если официальный файл приложен — вложи его байт в байт;
* иначе создай заглушку с шапкой `/* BA-SDK MOCK — the platform replaces this file at publish time */`, реализующую **ровно** интерфейс ниже. Заглушка автономна: режим `guest`, язык из `?lang=` или `en`, строки из `locales/`, при неудаче — встроенная копия `locales/en.json`; `submitResult` возвращает правдоподобный успешный ответ; `top()` — 10 фиксированных записей; хранилище — в памяти. Заглушка не использует запрещённые API.
* Игровой код не зависит от внутренностей заглушки — только от контракта.

```js
const ba = await BreaktimeArcade.init({ timeoutMs: 5000 });

ba.context = {
  sessionId, gameId, gameVersion,
  mode,            // "guest" | "user" | "autotest" | "preview"
  nickname,        // строка или null (гость)
  language,        // строка кода языка, список НЕ ограничен шестью
  fallbackLanguage,
  strings,         // объединённый словарь (портал может переопределить тексты)
  score,           // { type, unit, direction, minValue, maxValue }
  limits,          // { minPlaytimeSeconds, maxSessionSeconds, pauseOnBlur }
  trustLevel,
  seed             // строка; источник детерминизма
};

ba.ready();
ba.t(key, params);                                  // ICU/CLDR
ba.on('pause' | 'resume' | 'visibility' | 'session' | 'autotest:finish', cb);
await ba.submitResult({ value, durationMs, eventLog, seed, clientMeta });
// -> { status, rank, isPersonalBest, isRecord, trustLevel, code }
await ba.leaderboard.top(10);                       // -> { entries:[{rank,nickname,value}], myRank }
await ba.leaderboard.myBest();                      // -> { value, achievedAt } | null
await ba.storage.get(key);
await ba.storage.set(key, value);                   // суммарно ≤64 КБ
await ba.storage.remove(key);
const ctx = await ba.newSession();                  // ★ новый контекст: sessionId и seed
ba.exit();
ba.fail(code, message);
```

Правила использования:

1. Все обращения — с `try/catch` и таймаутами: инициализация 5 с, отправка 10 с, чтение 5 с. Отсутствие SDK не даёт «белый экран»: покажи экран ошибки с кнопкой «Повторить».
2. Не более 60 обращений к SDK в минуту. Не пиши в хранилище каждый кадр: дебаунс настроек ≥1 с. Ключи хранилища версионируй (`settings.v1`, `save.v1`) — данные переживают обновление игры.
3. ★ **Гость:** `submitResult` возвращает `{status:"guest", code:"E_GUEST_FORBIDDEN", rank:null, isRecord:false}`. Это **не ошибка**: результат показывается полностью, ретраи запрещены, рядом — строка «Результат не сохраняется» и приглашение зарегистрироваться.
4. ★ Ретраи (до 3, с экспоненциальной задержкой) — только при сетевых/временных отказах. Не ретраить: `guest`, отказ проверки, выход за границы, истечение сессии. Повторный вызов с тем же результатом безопасен: ключ идемпотентности один на сессию, свои ключи и заголовки не изобретай.
5. ★ `newSession()` возвращает новый контекст; используй **новый `seed`**, старый считать недействительным. При отказе (например, лимит) останься на экране результатов с нейтральным сообщением.
6. ★ Неизвестные события и поля контекста игнорируй молча — контракт расширяется обратно совместимо.
7. Секреты, e-mail, логин, идентификаторы пользователя игра не получает и не запрашивает.

## §7. Обязательные экраны и поток

1. **Стартовый экран**: название, крупная кнопка START, краткое правило в одну строку, переключатель звука, подсказки управления отдельно для ПК и сенсора.
2. **Игровой экран**: HUD со счётом и целью, кнопка паузы.
3. **Пауза**: затемнение, RESUME / RESTART / EXIT. При потере фокуса — автопауза, звук выключен, цикл не молотит вхолостую.
4. **GAME OVER** — яркий экран в стилистике аркадных автоматов 1990-х: крупная контрастная типографика, ретро-рамка, энергичная, но не мигающая анимация, звук фанфар. Показывает: GAME OVER, YOUR SCORE, BEST SCORE, место, TOP-10, PLAY AGAIN, EXIT. Надпись **NEW HIGH SCORE — только после `isRecord === true` от сервера**.
5. **Отправка результата**: состояние «сохраняем…», затем подтверждённый результат.
6. **Гость** (`mode === "guest"`, `nickname === null`): результат показывается полностью, ненавязчивая строка «Результат не сохраняется» и приглашение зарегистрироваться. Игра полностью играбельна и не ограничена.
7. **PLAY AGAIN** вызывает `ba.newSession()` и **полностью** сбрасывает состояние: таймеры, слушатели, объекты, звук, частицы, счёт, журнал событий; использует новый seed. После 20 перезапусков память не растёт.
8. **EXIT** вызывает `ba.exit()`.

Порядок для авторизованного игрока: завершение → `submitResult` → проверка → показ подтверждённого результата и места. До подтверждения рекорд не объявляется. `mode === "preview"` ведёт себя как гость.

## §8. Детерминизм, счёт и журнал событий

* ГПСЧ mulberry32 (или аналог) в `js/rng.js`, инициализируемый числовым хешем `ba.context.seed`. Вся влияющая на результат случайность — только из него.
* Один числовой результат в границах манифеста; счёт не может выйти за `maxValue`.
* Журнал событий передаётся в `submitResult`:

```json
{ "v": 1, "seed": "<seed>", "events": [
  { "t": 0, "k": "start", "d": {} },
  { "t": 1530, "k": "eat", "d": { "x": 7, "y": 3 } }
]}
```

`t` — целые миллисекунды от старта партии, не убывают, ≤ `durationMs + 1000`; `k` — только из `verification.eventKinds` (≤32 кодов); журнал ≤20 000 событий, ≤2 МиБ до сжатия и ≤256 КиБ gzip. Пиши значимые события, а не каждый кадр. `durationMs` — фактическая длительность партии без пауз.

## §9. Режим автотеста (обязателен)

При `ba.context.mode === "autotest"`:

* игра **сама** начинает партию без стартового экрана и без звука;
* использует `ba.context.seed`, играет детерминированно простейшей встроенной стратегией;
* завершает партию и вызывает `submitResult` с результатом в границах манифеста **не позднее 25 секунд** реального времени;
* немедленно завершает партию по событию `ba.on('autotest:finish', ...)`;
* не показывает модальных экранов, не ждёт ввода, не пишет ошибок в консоль;
* ★ не обязана выдерживать `minPlaytimeSeconds` — служебные сессии освобождены от минимума; верхняя граница 60 с.

## §10. Локализация

* Все без исключения строки — через `ba.t(key)`. Конкатенация и хардкод запрещены; пустые подписи и вывод технических ключей на экран запрещены.
* `locales/<lang>.json` для всех заявленных языков **и обязательно `en`**; одинаковый набор ключей; UTF-8; плюрализация через ICU (`{count, plural, one {# life} other {# lives}}`).
* ★ Список языков платформы расширяем: `context.language` может содержать код, которого нет в пакете. Порядок отката: `strings` (словарь портала) → `locales/<language>` → `locales/<fallbackLanguage>` → встроенная копия `en`. Игра не должна падать и не должна показывать ключ.
* Минимальный обязательный набор ключей (плюс собственные):
  `game_title, start, pause, resume, restart, game_over, your_score, best_score, new_record, play_again, exit, loading, error_sdk, error_network, result_saving, result_rejected, result_retry, session_expired, guest_notice, register_cta, controls_hint, orientation_hint, sound_on, sound_off, rank, top_scores`.
* Немецкий текст длиннее английского примерно на 35 % — интерфейс не должен ломаться. Шрифты — только из пакета, в формате `woff2`, с кириллицей и диакритикой.

## §12. Поведение при сбоях (обязательно реализовать)

| Ситуация | Поведение |
|---|---|
| Потеря сети во время партии | пауза, индикатор, состояние партии сохраняется в памяти |
| Восстановление сети | возобновление с того же места |
| Сбой при отправке результата | нейтральный статус, до 3 повторов, кнопка «Повторить отправку» |
| Отказ после повторов | понятное локализованное сообщение; результат не теряется до старта новой партии |
| Истечение сессии | сообщение «Сессия завершена», предложение сыграть снова, без повторов |
| Отказ проверки результата | нейтральный текст без обвинений и технических кодов, без повторов |
| Гость | результат показан полностью, уведомление о несохранении, без повторов |
| SDK не ответил за 5 с | экран ошибки с кнопкой «Повторить», не пустой экран |
| Потеря фокуса / сворачивание | автопауза, звук выключен, цикл не молотит вхолостую |

Потеря результата после длинной партии из-за кратковременного сбоя сети недопустима.

## §13. Качество, бюджеты, доступность

| Показатель | Порог |
|---|---|
| Критический путь (`assets.critical`, gzip, после подмены SDK) | ≤2 МБ |
| Полный пакет | ≤8 МБ желательно, ≤25 МБ предел |
| Старт до интерактива | ≤5 с, профиль Fast 4G (9 Мбит/с, 60 мс RTT) |
| FPS | ≥60 на ПК, ≥30 на эталонном Android |
| Память вкладки | ≤300 МБ, без роста после 20 перезапусков |
| Разрешения | 320×480 … 2560×1440, без выхода за iframe |
| Изменение размера | корректно, **без перезапуска партии** |
| Цикл рендера | один `requestAnimationFrame`, `devicePixelRatio` ≤2 |

* Управление осваивается за ≤30 секунд. Сенсорные цели ≥44×44 px, цели на ПК ≥24×24 px, текст ≥14 px, контраст ≥4,5:1. На игровой поверхности `touch-action: none`, учёт safe-area.
* Клавиши перехватываются только внутри игровой области и только после старта партии; страница портала должна прокручиваться, пока игра не начата. Canvas получает фокус по клику.
* Звук — только после жеста пользователя, с видимым переключателем; состояние сохраняется через `ba.storage`. Игра полностью работоспособна без звука; информация не передаётся только цветом или только звуком.
* **Мигание чаще 3 раз в секунду запрещено**, включая GAME OVER. `prefers-reduced-motion` уважается.
* Графика: собственный узнаваемый стиль, аккуратные ассеты, плавные анимации, частицы и обратная связь на каждое действие. Разрешение растровых ассетов не ниже отображаемого размера ×1 (×2 для Retina-критичных). Растяжение, размытие, временные заглушки, отладочные надписи и «серые квадратики» запрещены.
* Никаких бесконечных циклов, утечек памяти, дублирующихся слушателей и таймеров.

# Решения, принятые по умолчанию, и отклонения

1. **Документы выданы целиком, а не дельтами.** Дельта 2.1 ссылалась на нумерацию, которой не существовало; риск повторного рассогласования устранён консолидацией. Исторический реестр 4.0→4.1 остаётся в архивном файле 4.1.
2. **`capabilities.storage:"local"` запрещён в v1** (было разрешено). Причина — резервный режим opaque origin. Влияние на совместимость: игры используют только `ba.storage`; поле зарезервировано для v2.
3. **`catalog.description` расширен до 1600 символов** (было 1200) — немецкий и нидерландский тексты длиннее на 35 %. Добавлены обязательные `coverAlt` и `screenshotAlts` ради WCAG и полного автоимпорта.
4. **Хост игры привязан к `id`, а не к слагу** — смена названия и языка не меняет origin. Побочное следствие: `id` нельзя выбрать «красиво» после публикации.
5. **Гостевая отправка нормализуется SDK**, а не показывается как ошибка. Требуется SDK 1.1; игры с заявкой `^1.0` совместимы (расширение обратно совместимое).
6. **Эпохи рекордов** вместо удаления старых таблиц: данные не теряются, публичная таблица обнуляется только по решению владельца.
7. **Служебные режимы исключены из всех продуктовых агрегатов** — метрики после автотестов остаются чистыми.
8. **Юридические формулировки** (16+, резерв никнейма 24 месяца, DSA/EN 301 549) сохранены из 4.1 и по-прежнему требуют подтверждения профильным юристом до публичного запуска.
